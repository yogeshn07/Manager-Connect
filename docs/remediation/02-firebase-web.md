# REM-02: Firebase Web SDK Configuration

## Problem

`firebase_core` and `firebase_messaging` are in pubspec.yaml but no Firebase web configuration exists. On web, Firebase is skipped via `kIsWeb` guard. This blocks all push notification functionality.

## Severity: HIGH

## Risk: Feature Blocker

Without Firebase web config:
- No FCM push notifications on web
- No background message handling
- NotificationService.initialize() is skipped entirely on web
- Push token registration never fires

## Affected Modules

- Notifications (push delivery)
- All modules that dispatch notifications (recognition, activities, challenges)

## Architecture

Firebase on Flutter web requires:
1. A Firebase project in Google Cloud Console
2. `flutterfire configure` to generate `firebase_options.dart`
3. Firebase JS SDK scripts in `web/index.html` OR auto-configuration via `firebase_options.dart`

### Option A: FlutterFire CLI (Recommended)

```bash
# Install FlutterFire CLI
dart pub global activate flutterfire_cli

# Configure (generates firebase_options.dart + updates web/index.html)
flutterfire configure --project=manager-connect-prod
```

This generates `lib/firebase_options.dart` with platform-specific config.

### Option B: Manual Configuration

Add to `web/index.html` before `flutter_bootstrap.js`:
```html
<script src="https://www.gstatic.com/firebasejs/10.12.0/firebase-app-compat.js"></script>
<script src="https://www.gstatic.com/firebasejs/10.12.0/firebase-messaging-compat.js"></script>
<script>
  firebase.initializeApp({
    apiKey: "...",
    authDomain: "...",
    projectId: "manager-connect-prod",
    storageBucket: "...",
    messagingSenderId: "...",
    appId: "..."
  });
</script>
```

### main.dart Changes

Remove the `kIsWeb` guard and use `DefaultFirebaseOptions`:
```dart
await Firebase.initializeApp(
  options: DefaultFirebaseOptions.currentPlatform,
);
```

### NotificationService Changes

Remove the `kIsWeb` guard. Web FCM uses the browser's Notification API (no native push channel needed).

## Files Impacted

| File | Change |
|------|--------|
| `frontend/lib/firebase_options.dart` | NEW — generated by flutterfire configure |
| `frontend/web/index.html` | MODIFY — Firebase JS SDK scripts added |
| `frontend/lib/main.dart` | MODIFY — remove kIsWeb guard, add DefaultFirebaseOptions |
| `frontend/lib/shared/services/notification_service.dart` | MODIFY — remove kIsWeb guard |
| `frontend/web/firebase-messaging-sw.js` | NEW — service worker for background messages |

## Dependencies

- Google Cloud project with Firebase enabled
- Firebase Cloud Messaging API enabled
- FCM server key for Edge Function `send-notification`
- `Deno.env.get('FCM_SERVER_KEY')` in Edge Function runtime

## Validation Steps

1. `flutterfire configure` completes without errors
2. `firebase_options.dart` generated with valid config
3. `flutter build web` succeeds
4. App loads without Firebase errors in console
5. `FirebaseMessaging.instance.getToken()` returns a valid FCM token
6. Token is stored in `profiles.push_token` via REST
7. Sending a test notification via `send-notification` EF delivers to browser

## Rollback Plan

Delete `firebase_options.dart`. Restore `kIsWeb` guard in main.dart. App reverts to no-push-on-web behavior.

## Estimated Effort: 2-3 hours

## Note

This requires a real Firebase project. Cannot be tested with Supabase local dev alone. The FCM server key must also be configured as a Supabase Edge Function secret.
